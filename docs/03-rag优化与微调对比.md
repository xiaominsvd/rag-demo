# RAG 优化手段

## 常见优化

- 切块策略：按语义（标题/段落）切比固定长度切效果更好；给 chunk 加标题或摘要能提升检索。
- 混合检索：向量检索 + 关键词检索（BM25）取并集，兼顾语义和精确匹配。
- 重排序（rerank）：先用向量召回 20 个，再用 cross-encoder 精排取前 3 个。
- 查询改写：把用户问题改写成更适合检索的形式，或做 HyDE（先让模型假设一个答案再去搜）。
- 引用约束：在 prompt 中要求模型只基于资料回答，并标注来源。

## RAG vs 微调

| 维度 | RAG | 微调 |
|---|---|---|
| 知识更新 | 加文档重建索引即可，分钟级 | 要重新训练，小时~天级 |
| 成本 | 低 | 高（算力+数据标注） |
| 适用场景 | 知识问答、引用溯源 | 风格、格式、特定任务行为 |
| 幻觉 | 有资料约束，较少 | 仍可能编造 |

两者不互斥：很多生产系统是"微调管行为风格，RAG 管知识"。
